Bundle split (from the built `dist/index.html`): `index-*.js` is the entry script, and
`rolldown-runtime-*.js` and `api-*.js` are `modulepreload`ed, so those three load on every
first page. `RecipeForm-*.js` is lazy and loads before the form shows on `/recipes/new` and
`/recipes/:id/edit`. `DeleteRecipeButton-*.js` (the Radix `AlertDialog`) is lazy and loads on
`/recipes/:id` after the recipe has painted; Lighthouse sees it in the same page load. Its
transfer sizes agree: 124.9 kB on `/`, 138.8 kB on `/recipes/:id`, 144.1 kB on `/recipes/new`.

## Misses

### 1. `/recipes/new` first-load JS 156.3 kB, over 150 kB (Must fix; fixed, now 143.6 kB)

- **Evidence (9437ff5):** Lighthouse `network-requests` on `/recipes/new` loaded 157.2 kB of
  script: `index` 88.6, `recipeQueries` 47.2, `RecipeForm` 19.2, `NewRecipePage` 1.3, runtime
  0.9.
- **Cause:** the Radix `AlertDialog` (`DeleteRecipeButton.tsx`, `import { AlertDialog } from
  "radix-ui"`) with `react-remove-scroll`, `react-dismissable-layer` and `tslib` was in the entry
  chunk of every route, about 14 kB gzip, though it is used only after a click on Delete on
  `/recipes/:id`.
- **Fix (91a1456):** `DeleteRecipeButton` is lazy inside `RecipePage`. The entry went from
  136.8 to 124.8 kB on every route; `/recipes/new` is 143.6 kB with the form (6.4 kB margin).

### 2. `/recipes/new` mobile LCP 2.13 s, over 2.0 s (Must fix; fixed, now 0.75 s)

- **Evidence (9437ff5):** `largest-contentful-paint` 2133 / 2131 / 2133 ms. The LCP element
  was the form's intro paragraph ("A title, the ingredients and the steps are all a recipe
  needs."), inside `RecipeForm`, with all of its time in element render delay.
- **Cause:** three JS fetches in a row before that text existed: the entry chunks, then the
  lazy `NewRecipePage` route chunk, then `RecipeForm`. The heading was in the lazy page chunk
  too.
- **Fix (91a1456):** route-level `lazy()` is gone; only the form is lazy (`LazyRecipeForm`),
  and the page's heading and intro line render outside it. The LCP element is now the intro
  `main > p.mt-3`, painted with the first render: 754 / 753 / 754 ms, the same as `/`.
  `/recipes/:id` also improved, from 1.96 s to 1.81 s (1805 / 1805 / 1807 ms), as its entry
  JS is 12 kB smaller.

## Worth doing (within budget)

- **`/recipes/:id` LCP 1.81 s is a JS → data waterfall.** The LCP element is the description
  `<p>` (`article > p.mt-3`), shown after the entry JS runs and then `GET /api/recipes/:id`
  returns. The margin is now 190 ms; keep the 125 kB entry from growing.
- **`unused-javascript` 62–71 KiB** on every route (was 74–81): mostly `react-dom`, plus the
  zod parsers and router code that the current page doesn't call. No metric cost today.
- **The list query is a collection scan with an in-memory sort.** `explain` of
  `find({ ownerId }).sort({ createdAt: -1, _id: -1 }).limit(50)` (first run): `SORT` over
  `COLLSCAN`, 124 docs examined for 50 returned; the only index is `_id`. 3 ms today. The
  design's index `{ ownerId: 1, createdAt: -1, _id: -1 }` (`docs/system-design.md` §5) needs
  the `db:indexes` script that is still to come; land it with cursor pagination in M3.
- **`e2e/a11y.spec.ts` does not scan `/recipes/:id` or the open delete dialog.** The observer
  scan found 0 violations there; add both to the spec so a regression fails the run.
- **Render-blocking CSS** (`render-blocking-insight`): `index-*.css`, 3.7 kB, est. 140–150 ms
  on mobile. Unchanged since M1; leave it.
- **Agentic Browsing 50** (not in the budgets): `llms-txt`, `ard-schema`. No action.

## Carried from M1

- **pino-http logs every request and response header: still open.** `server/src/app.ts:18`
  is `app.use(pinoHttp({ logger }))` with no `redact` or custom serializers. Each request line
  carries the 13–14 request headers (`user-agent`, `referer`, `sec-ch-*`, `if-none-match` …)
  and all 13 helmet response headers: about 1.4 kB per line in the observer log, 1.7 kB in the
  e2e log. Request bodies are not logged (good). Still Worth doing, and **Must fix before auth
  lands (M7)**: `pinoHttp({ logger, redact: ["req.headers.cookie", "req.headers.authorization",
  'res.headers["set-cookie"]'] })`, or serializers that keep only method, URL, status and time
  (which would also cut the line to ~250 bytes).
- **"One bundle" note: resolved.** M1 said to split with `lazy()` only if first-load JS neared
  150 kB. M2 added `react-router`, `zod` (response parsing), Radix and TanStack Form. The form
  and the delete dialog are now lazy, and the entry is 124.8 kB (+27 kB on M1).
